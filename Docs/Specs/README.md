## Working conventions

- Keep all specifications in `Docs/Specs`.
- Mark documents Draft, Accepted, or Superseded; record changes to accepted decisions.
- Separate sourced findings, hypotheses, and proposed requirements.
- Link research claims to primary sources and record the date checked.
- Add detailed UI, API, data, and deployment specifications after the feasibility work informs them.
- No application code or experiments have been implemented yet.
